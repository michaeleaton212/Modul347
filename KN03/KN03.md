## 5. Gemeinsamkeiten und Unterschiede (Erklärung)

### 5.1 Gemeinsamkeiten

- Alle Container besitzen ein Netzwerkinterface (typisch `eth0`) mit einer IPv4-Adresse.
- In beiden Fällen existiert ein Default Gateway (Docker stellt pro Bridge-Netz ein Gateway bereit).
- Kommunikation innerhalb desselben Netzwerks ist grundsätzlich möglich (Layer-2 über die Docker-Bridge).

### 5.2 Unterschiede

**(1) Subnetz / IP-Bereich**

| Netzwerk       | Subnetz          |
|----------------|------------------|
| default bridge | `172.17.0.0/16`  |
| tbz            | `172.18.0.0/16`  |

**(2) Namensauflösung (DNS)**

- **default bridge:** Containername wird standardmässig **nicht** automatisch aufgelöst → `ping busybox2` kann „bad address" liefern
- **user-defined bridge (tbz):** Docker bietet einen eingebauten DNS-Dienst → Container können sich im selben user-defined Netzwerk über Namen erreichen (z.B. `ping busybox4` von `busybox3`)

**(3) Netzwerkisolation / Routing**

Container in unterschiedlichen Docker-Bridge-Netzen können standardmässig **nicht** direkt miteinander kommunizieren, da Docker kein Routing zwischen separaten Bridge-Netzen einrichtet.

> **Ergebnis:** Pings von `172.17.x.x` nach `172.18.x.x` schlagen fehl (und umgekehrt).

### 5.3 Schlussfolgerung

User-defined Netzwerke ermöglichen:
- klare **Segmentierung (Isolation)** zwischen Containergruppen
- **definierbare Subnetze**
- **funktionierende Namensauflösung** innerhalb des Netzwerks

Das default bridge Netzwerk ist eingeschränkt (DNS/Management), daher ist die Kontrolle über Kommunikationskanäle geringer.

## 6. Betrachtung KN02

### 6.1 In welchem Netzwerk befanden sich die beiden Container?

> **Antwort (typisch):** Beide Container befanden sich im gleichen Docker-Netzwerk, sehr wahrscheinlich im **default bridge** (sofern kein user-defined Netzwerk verwendet wurde).

### 6.2 Wieso konnten die miteinander reden?

Weil beide Container:

1. im gleichen Netzwerksegment (gleiche Docker-Bridge) waren → Layer-2 Erreichbarkeit per IP ist gegeben
2. in KN02 zusätzlich ein `--link` verwendet wurde (legacy), wodurch Name/Erreichbarkeit erleichtert wurde (z.B. via Einträge/Mechanismen für Namensauflösung)

> **Konsequenz:** Im selben Netzwerk ist Kommunikation möglich; `--link` kann zusätzlich die „finden sich per Name"-Problematik im default bridge umgehen.
