## 5. Gemeinsamkeiten und Unterschiede (Erklärung)

### 5.1 Gemeinsamkeiten

- Alle Container besitzen ein Netzwerkinterface (`eth0`) mit einer IPv4-Adresse.
- In beiden Netzwerken existiert ein Default Gateway (Docker stellt pro Bridge-Netz ein Gateway bereit).
- Kommunikation innerhalb desselben Netzwerks ist möglich (Layer-2 über die Docker-Bridge).

### 5.2 Unterschiede

**(1) Subnetz / IP-Bereich**

| Netzwerk       | Subnetz         | Gateway      |
|----------------|-----------------|--------------|
| default bridge | `172.17.0.0/16` | `172.17.0.1` |
| tbz            | `172.18.0.0/16` | `172.18.0.1` |

**(2) Namensauflösung (DNS)**

- **default bridge:** Containernamen werden **nicht** automatisch aufgelöst → `ping busybox2` liefert `bad address`
- **user-defined bridge (tbz):** Docker bietet einen eingebauten DNS-Dienst → Container können sich über Namen erreichen (z.B. `ping busybox4` von `busybox3` funktioniert)

**(3) Netzwerkisolation / Routing**

Container in unterschiedlichen Docker-Bridge-Netzen können **nicht** direkt miteinander kommunizieren — Docker richtet kein Routing zwischen separaten Bridge-Netzen ein.

> Pings von `172.17.x.x` nach `172.18.x.x` schlagen fehl (und umgekehrt).

### 5.3 Schlussfolgerung

User-defined Netzwerke ermöglichen:
- klare **Segmentierung (Isolation)** zwischen Containergruppen
- **definierbare Subnetze**
- **funktionierende Namensauflösung** innerhalb des Netzwerks

Das default bridge Netzwerk ist eingeschränkt (kein DNS, weniger Kontrolle), daher ist die Verwaltung von Kommunikationskanälen schwieriger.

## 6. Betrachtung KN02

### 6.1 In welchem Netzwerk befanden sich die beiden Container?

Beide Container befanden sich im **default bridge** Netzwerk (kein user-defined Netzwerk wurde in KN02 verwendet).

### 6.2 Wieso konnten die miteinander reden?

Weil beide Container:

1. im gleichen Netzwerksegment (gleiche Docker-Bridge) waren → Layer-2 Erreichbarkeit per IP ist gegeben
2. in KN02 zusätzlich `--link` verwendet wurde (legacy), wodurch die Namensauflösung im default bridge ermöglicht wurde

> **Konsequenz:** Im selben Netzwerk ist Kommunikation per IP möglich; `--link` löst zusätzlich die Namens-Problematik im default bridge.
